# Formula validation sample

`formulas-sample.xlsx` — 46 formulas across 7 sheets (Math, Stats, Logic,
Text, Lookup, Dates, Refs, Errors), generated by `generate-formulas-sample.mjs`
using raw SheetJS (so it independently exercises the adapter's read path).

`validate-formulas.mjs` loads it through `XlsxAdapter.read` → `EngineWorkbook`
and checks every formula against independently computed expectations in
`formulas-expected.json`. Currently **46/46 green**.

## Findings fixed during validation

1. **SheetJS drops formula cells without a cached value.** `{t:'n', f:'...'}` 
   round-trips as a missing cell; `{t:'n', v:0, f:'...'}` survives. The
   generator uses the `v:0` placeholder (values are always recalculated on
   read, never trusted). The xlsx-adapter does the same on write.
2. **HyperFormula had no `CONCAT`** (only legacy `CONCATENATE`). Added
   `packages/engine/src/function-aliases.ts`: a thin alias plugin
   auto-registered with the engine. Covered by engine tests.

## Known Excel-compat gaps (upstream, not fixed here)

- **Bare `FALSE`/`TRUE` as literals**: HyperFormula parses `FALSE` as a named
  expression and errors; `FALSE()` works. The sample uses `FALSE()`.
  (Upstream parser behavior; Excel accepts both.)
- **SheetJS round-trip limits** (see packages/xlsx-adapter/README.md):
  unknown OOXML parts (VBA, embedded objects) are dropped, error cells read
  back as blank, encrypted workbooks unsupported.
