## Headline

The verification *code* is largely sound (Firebase/JWT/engine-token verification, ownership 404s, tier caps, SQL connector, vault discipline all PASS). The deployed *configuration and defaults* negate it in three Critical places, and two authorization surfaces are incomplete. **3 Critical, 5 High, 8 Medium, 8 Low — all FILED with exact remediations; no code fixes were landed in this pass (per-item reasons in "Fixes").** The three Criticals should be applied as one coordinated change with the deploy, before public exposure:

- **F-1** — `POST /auth/login` live in prod: unauthenticated impersonation of any user.
- **F-2** — Engines deployed in proxy mode trusting a spoofable `x-principal`; the secret env set is read by no code.
- **F-11** — `PY()` formula function executes file-supplied Python in the server engine process by default (probe-confirmed: arbitrary file write + host env read via an allowlisted module — no sandbox escape even required).

F-1+F-2 are a pair: closing only one leaves the other full bypass open.
